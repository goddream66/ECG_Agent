# ECG Agent 事件复核与两层记忆

## 本轮范围

使用 `quality-as-hint` 逐窗回放。ECGFounder 对已到达的十秒窗口评分，原状态机维护候选、确认、持续和结束。Qwen3-8B 负责复核可能被切成多个片段的事件，每对事件最多生成一次。第一轮固定已有证据，测量模型是否能改善区间判断。第二轮再比较按需补测。孤立候选、事件外边界和未形成任何候选的漏报分别评估。

## 两层记忆

| 层 | 写入内容 | 何时读 |
|---|---|---|
| 窗口级 | 当前任务与通道、窗口起止和可用时间、策略判定及原因、当前阈值、各导联 AF/AFL 原始分数、质量状态及具体提示、各工具证据 ID。未调用、调用失败、有质量提示分别保存。 | 逐窗轨迹和证据账本落盘。在线索引只保留复核跨度内的近期记录。复核时读取间隔及两侧边界。 |
| 事件级 | ID、候选起点、估计区间、首次观察、实际确认和关闭时刻、关闭原因、支持、反向、未知窗口及其引用。事件摘要额外按导联汇总质量已测窗数、带提示窗数、失败窗数，记录边界证据指针。 | 右侧事件确认时读取已关闭的左事件以及当时的右事件摘要。右侧以后延长的窗口不能进入该次请求。 |

证据是带时间的原始工具结果，摘要由程序增量计算。参考标签只在评估阶段载入。每次复核保存输入、决定、引用、实际信号游标、耗时和失败原因。修订输出独立于最初的预测和报警日志。

## 触发与执行

1. 左事件已确认且已关闭，右事件刚确认，两段之间存在一个正长度、至多 60 秒的间隔。取间隔全窗和左右各两个相邻窗，且所有证据必须在右事件确认时已到达。每对相邻事件最多一次。
2. 系统先提供事件摘要和紧凑的窗级证据。Qwen 可以建议保持分开、合并、只关联事件身份或证据不足，并引用包内的证据别名。别名映射回账本原 ID。证据不足可指出需要补测的窗和导联，第一轮只记录这一请求。
3. 导联质量提示与节律分数分别呈现。有提示的分数仍保留，未测或失败没有可用性结论，两路评分使用同一个 ECGFounder，也可能一起误判。只有每个间隔窗都存在已测且无质量告警、分数达到开始阈值的导联证据，才允许填入整个间隔。必须引用每个间隔窗对应的评分和质量。这个规则是实验约束，需通过参考区间验证。
4. 如果间隔中有尚无证据覆盖的窗口，可以记录两段可能相连。关联记录不会扩大 AF/AFL 预测时长。任意协议错误、非法引用或证据不足都保留基础输出。间隔内的错分由独立评价统计。
5. 后续再加两类触发：孤立候选关闭且片段内外证据相反时复核误报，事件结束且边界附近存在冲突或未知时复核起止。沿用同一证据结构，只允许修订已到达、且有相应证据的网格边界。补测阶段让规则与 Qwen 共用预算、工具和因果窗口权限。

## 对照实验

使用同一批 AFDB 完整记录、两种主导联、同一 `quality-as-hint` 候选和同一 60 秒上限。对照未复核、固定间隔合并、同证据规则合并、Qwen 受证据约束的复核。固定间隔规则按相同候选直接连接。同证据规则合并所有通过上述证据约束的间隔。Qwen 在相同约束下选择要接受的间隔。

### 运行方式

在服务器代码目录激活项目环境，令 `SOURCE` 指向已完成的质量实验目录，`OUTPUT` 指向共享盘上一个新目录。

```bash
python -m cardioagent.ecg_agent.experiments.episode_review \
  --source "$SOURCE" --output "$OUTPUT" \
  --references "$ECG_AGENT_STORAGE/data/afdb_tasks_server/evaluation_references.jsonl" \
  --model-path /data/1shared/gaojiajun/LLM_Model/Qwen3-8B \
  --devices cuda:0 cuda:1 cuda:2 cuda:3
```

`--prepare-only` 只生成证据包并统计候选数，`--records` 可选择少量记录检查。`packets/` 和 `decisions/` 按通道和记录保存请求和返回，`COMPARISON.md` 是对照表，`comparison.json` 包含逐记录指标和耗时。离线回放用流式游标恢复当时可见证据，写出的预测用于事后区间评分。实际报警延迟应继续从原始事件更新读取。

报告事件 F1、时间召回、非 AF 报警时间、长事件碎片、跨越参考事件的错误合并和连接所新增的非 AF 时间。记录候选数、模型有效输出、接受及拒绝数、每小时调用、延迟和 token 数。以记录为单位计算配对区间，标记 AFDB 为探索性实验。只有相对同证据规则有改进，才能将这项收益归因于 LLM。若规则和模型完全相同，或模型收益伴随明显代价，则按实际结果报告。

## 代码边界与参考

- `memory/` 保存结构化数据和按时间取证。借鉴短期窗口与长期事件摘要分层，以及小入口脚本的结构。[EventMemAgent](https://github.com/lingcco/EventMemAgent)
- `harness/` 执行一次模型调用并校验结构化建议。模型、状态和阶段输出分开，借鉴状态中保存原始数据、节点按需将它格式化为提示的设计。[LangGraph](https://docs.langchain.com/oss/javascript/langgraph/thinking-in-langgraph)
- `experiments/` 读取已有回放产物，独立加载参考答案，生成对照和审计。输出存服务器共享盘的独立运行目录。
