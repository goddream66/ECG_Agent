# CardioAgent 流式 ECG 自主决策与事件记账方案

2026-11-22 修订。原 C/D 对照基线为 `9bd292a`。本地已接入自主起止、固定或自主复核两组策略，接口与测试位置见配套机制文档第 7 节。真实 Qwen 的效果另行验证。

配套材料：[Qwen 中英文提示词、工具说明与从零操作示例](prompts/autonomous_event_v1/README.md)。

[查看一次复核的四步机制、完整事件示例，以及与 C/D 运行代码的逐项对照](ECG_AGENT_REACT_EVENT_MECHANISM.md)。

## 1. 本次修订的主线

研究问题是：在因果约束下，Qwen 能否判断**当前知道什么、还缺什么、此刻是否值得作出事件决定、如果等待应何时回来**？待验证的收益是减少证据不足时的误开和误关。等待也可能延误报警、错过短事件；两方面都要测。

上一版把“等待”主要处理为记录不确定，然后在固定的下一个十秒窗复核。本版把**主动延迟决定并选择复核时刻**列为主实验变量。保留原两窗状态机和固定十秒复核作为对照。自主组由 Qwen 决定 OPEN、CLOSE 和复核时间；程序负责按时交付已到达数据、保存事件身份、验证引用及执行合法动作。没有因为累计两窗、超时或到达流末而自动推断心律改变的规则。

**阅读顺序。** 第 2–3 节给出问题依据；第 4–7 节沿一次实际决策走完“观察、取证、决定或等待、唤醒和记账”；第 8–10 节给出实施顺序与验证方式。

## 2. 先看四个实际判断点

开发片段为 AFDB 04936 的 1550–1850 秒。参考 AFIB/AFL 合并事件为 1654.764–1791.044 秒。下表时间是模型已经看到窗口右端时的游标，参考时间仅供离线评分。

| 游标与版本 | 模型实际做了什么 | 由此设计的检查 |
|---|---|---|
| 1560 秒，旧 D | 首窗没有历史，状态为 IDLE。Qwen 读到 AF 0.085、AFL 0.044、RR-CV 0.011，并称没有强支持，却以“没有终止迹象”为理由提交支持 | 首窗也会出现任务理解错误。单独试验按状态提问，检查模型能否为“提出候选”给出本窗正向依据 |
| 1660 秒，短编号 C | 上一窗已关闭事件 1。新窗读到 AF 0.955、AFL 0.543，却再次引用旧事件 1 和旧终点 1649.164；重试后仍失败 | 区分“现在无事件”和“过去有事件”。显式显示最近一次已执行变更，按当前状态限制可提交的操作 |
| 1720 秒，短编号 D | 理由承认 AFL 0.9924 和相对规则的 RR 可与房扑相容，最终提交 DEFER + negative | 单独核对理由是否支持本窗证据方向。AF 与 AFL 取并集，亚型不确定仍可能支持合并目标 |
| 1800 秒，新旧 C | 旧 C 提出 1800 秒结束，边界校验拒绝；短编号 C 提出 1799.244 秒的末次检出心搏并获接受。参考终点为 1791.044 秒 | 分别评价转变方向、边界误差和实际决定的时间。通过区间检查只能说明时间合法，不能证明末次心搏定位了节律转变 |

这几个游标来自同一记录。旧版在这段回放没有成功执行 CLOSE，因此缺少同状态下的自然对照。短编号结果用于挑选故障场景，不能单独证明短编号导致错误。

## 3. 回退版的约束与上下文开销

1. 每个正常复核窗口都要完成一次最终提交。允许 `DEFER + conflict/unavailable`，因此存在暂缓路径。问题在于一个提交同时绑定节律解释与事件动作。
2. `WindowEventDecision` 强制 `KEEP_OPEN` 与 `support` 双向对应。在空闲状态要提交新的阳性证据，Qwen 也必须说“保持打开”。同一份提示在空闲和活动状态下都展开介绍终点定位。
3. 默认带入至多六窗历史，模型可以检索更早的已取得证据。当前在线入口保留至多约 120 秒原始波形供合法补测。历史可检索范围与原始波形可重测范围需要分别显示。此前这段 C/D 四次连续回放均未调用历史检索。
4. 当前成功的本窗节律证据对 `support/negative/conflict` 有引用要求。已到达的历史可以解释趋势。旧分数只描述它自己的测量区间，不能直接充当当前窗口的观测。
5. 首轮保留旧长哈希账本及旧版当窗短编号。最终清单里的 `E1` 可以逐窗复用，在线测量与历史消息仍沿用当前基线格式。

## 4. 一次决策从哪里开始

1. **首窗到达。** Qwen 获取任务定义（AFIB 或 AFL 均计入目标）、当前游标、可访问的波形范围和工具清单。事件账本为空时明确显示“无开放事件”。不构造六个空历史窗，也不预先替模型运行 ECGFounder。
2. **Qwen 选择如何取证。** 可以测当前或已保留的过去信号，可以查询本记录的测量和事件记忆，也可以在现有证据足够时直接提交。读取记忆和补测可以在同一复核内进行，无须先提交延迟决定。ECGFounder 每次仍接收合法十秒输入；其他工具遵守各自的区间约束。
3. **Qwen 记录本次观察，并决定现在做什么。** 当前已经有足够证据时，首窗即可正式开事件。尚不能回答起点、是否持续或终点问题时，可以将问题挂起，自己选下一次回来复核的时间。
4. **调度器执行时间安排。** 未到复核时刻只接收并缓冲信号。不会逐十秒偷偷调用 Qwen、计算未来分数或给跳过的窗口填标签。醒来后，Qwen 看到新的游标、上次留下的问题及账本当前状态，可以查历史、补测中间已到达的区间、作决定或再次等待。

## 5. 把观察、事件操作和复核时刻分开

| 层次 | 拟议字段与选项 | 例子 |
|---|---|---|
| 当前观察 | `assessment` 为 `SUPPORTS_TARGET`、`AGAINST_TARGET`、`UNCERTAIN`；同时给出实际测量区间、证据引用和简短依据。不确定时注明缺测、质量问题、测量冲突或区分力不足 | 两路结果冲突且当前难以解释，可以明确记录 UNCERTAIN |
| 本次事件操作 | `OPEN` 正式开事件；`CLOSE` 正式结束当前开放事件；`RECORD_ONLY` 记录本次观察，本轮没有要追办的事件问题；`DEFER_DECISION` 把一个具体问题挂起，并安排回来处理 | 本窗已有反对持续的证据，但终点位置仍不清楚，可用 AGAINST_TARGET + DEFER_DECISION |
| 复核安排 | 自主时间组的每次有效提交都包括未来的 `next_review_s`（流已结束除外）。DEFER 另存待解决的问题、等待理由及已有证据。其余动作也能安排下次常规巡视 | 没有开放事件、当前证据清楚时，可以 RECORD_ONLY 并安排下一次巡视，不计作“证据不足” |

**不确定描述证据，延迟描述行动。** 遇到不确定，Qwen 可以马上查已获得的记忆或补测备用导联；可能当场解决。反过来，即使确信当前窗倾向非 AF/AFL，也可以把“前一事件到底在哪一秒结束”留待复核。两个字段分别记录，才知道等待究竟解决了什么。

**按可执行动作提问。** 空闲时只提供 OPEN、RECORD_ONLY、DEFER_DECISION；已有开放事件时只提供 CLOSE、RECORD_ONLY、DEFER_DECISION。运行时绑定事件身份，不让模型抄写账本 ID。保持同一事件开放不需要反复提交 KEEP_OPEN。已开事件中的未知时间单列。对齐 ECG-Scroll 的主负荷按最终报告区间计算，单列的证据支持负荷只计得到正向测量支持的秒数。只有强度分数或一个末次心搏位置，不自动构成精确的起止边界。首窗已经呈现目标而起点不可见时，仍可 OPEN，并登记“首次观察即存在，起点未知”。

## 6. 等待与唤醒如何落地

- **谁选择时间。** Qwen 给出自己期望复核的绝对记录时间，使用秒。若采集端目前每十秒交付一批数据，调度器在首个覆盖目标时刻的到达批次唤醒，分别保存请求时刻、实际唤醒时刻和可见信号终点。首版按实际批次记录可见游标，不伪称中间时刻已经完成推理。测量边界与事件边界仍可位于窗内。
- **等什么。** DEFER 必须说清待解决的问题，例如“间隔中的低分能否得到后续节律和另一导联的佐证”。如果所缺信息现在就可取得，模型仍可选择立即测量或检索。首版用时间唤醒，无须在后台持续跑 Founder 来监视某个分数阈值。
- **再次等待。** 允许重复 DEFER，每次绑定同一待办、保留原始提出时间，并记录新获得了什么、为什么还要等。唤醒后可关闭待办、继续挂起，或明确撤回先前怀疑。撤回疑问不会删除原观察。
- **避免空转或悄悄漏扫。** 请求时间须晚于当前游标；非法请求允许有界重试。为比较各组，可预先登记最大复核间隔及其与原始波形缓冲长度的关系，作为调度约束；记录每次限幅及原因。不给任何限幅触发绑定诊断动作。即使在缓冲内，跳过复核仍可能漏掉完整短事件，评价时必须保留这些记录。
- **流提前结束、断流与重启。** 若未到预约时刻就结束，登记未解决待办和开放事件的右截断；可在预先声明的统一流末复核条件下交付最后一批已到达数据，单列来源。没有有效 CLOSE 就不能算作模型成功关闭。重启时恢复待办和已执行事件版本，重复唤醒或动作不得重复记账。

**示意轨迹，非真实预测。** 设已有开放事件，游标 1700 秒。Qwen 获取一条反向测量，先检索上次可靠支持，怀疑短暂波动，提交 AGAINST_TARGET + DEFER_DECISION，请求 1720 秒复核。1710 秒只缓冲。1720 秒醒来后，允许检查 1700–1720 秒已到达波形。若支持恢复，记录恢复并解决疑问，开放事件继续；若看见可信的局部转变，可以在 1720 秒提交 CLOSE 并给出有依据的较早终点；若依然无法区分，可再次等待。三条分支都保留 1700 秒的初始判断。后来取得的证据不能写成 1700 秒已经知道的事实。

## 7. 记忆、待办和事件账本分别保存什么

| 存储对象 | 写入与读取 | 必须保留的内容 |
|---|---|---|
| 测量与观察记录 | 工具执行和提交后由程序写入；Qwen 可按区间、导联、工具检索 | 测量区间、可用时刻、工具状态、规范证据 ID、实测值、观察方向。将“未测”“测量失败”“模型动作失败”“证据不足”区分开 |
| 事件账本 | 只有合法的 OPEN/CLOSE 才改变正式事件身份与开放状态。Qwen 可读取当前或历史事件 | 事件 ID、估计起止及边界不确定性、首次观察、实际开关决定时刻、相关证据、支持与未知区间、修订和截断 |
| 待复核问题 | DEFER 时建立；唤醒时归还 Qwen；随后追加处理结果 | 疑似起点、持续或终点问题，涉及区间，关联事件（可为空），理由、既有证据、预期新增信息、预约与实际唤醒时间、解决或未解决 |
| 调用审计 | 运行时保存，不默认全部塞回模型 | 当时真正可见的消息、合法工具、模型原始动作、校验与重试、实际执行、token 与耗时 |

待办可以只是同一运行目录的一类追加日志，无须引入新的记忆模型。首次疑似发作可以先留待办，不由系统擅自创建正式事件。账本报告事实，待办报告疑问。默认送入紧凑的状态、待办及近期实测事实；Qwen 自己选择是否检索完整历史。历史测量和模型的旧解释分开呈现。本轮沿用旧版证据编号及账本，避免同时改变引用方式。保留因果审计，检索或补测都不能取到游标之后的数据。

## 8. 代码修改的先后关系

1. **冻结基线。** 保存代码、权重、提示和 schema 指纹、真实决策快照及运行参数。用旧入口重放，保持原预测和日志可核对。
2. **实现观察及事件操作协议。** 在 `harness/event_decision.py` 定义字段和状态合法动作；在 `harness/react.py` 按状态生成简短任务。取证与提交阶段分开；提交时允许 DEFER。格式失败记 ACTION_ERROR，保留已有事件与证据，不伪装成模型主动等待。
3. **实现只执行合法提议的账本。** 在 `memory/events.py` 和 `agent.py` 增加自主模式。旧模式仍按原两窗规则运行；自主模式取消连续支持自动创建、自动关闭等判断。对边界和引用做形式校验，生理解释的正确性另行评价。
4. **接入时间调度和记忆恢复。** 在回放入口分开“波形已到达”和“该唤醒 Qwen”；启动首次复核，执行预约，再恢复待办。存储运行清单和进度，确保重试、恢复以及段末处理可复现。
5. **独立接入上下文精简。** 先去掉可回指的重复工具结果，再压缩近期时间线。最终阶段仍能看见用来定位边界的测量细节。单独开关，避免把减少输入 token 的收益混入自主等待实验。

## 9. 先证明各个环节正确，再验证等待是否有用

**第一层，工程测试。** 覆盖首次即 OPEN、首窗不确定并预约、检索后当场解决、反向观察但暂缓关闭、再次延迟、空闲状态拒绝关闭、已关闭后发现新事件、非法复核时间、唤醒落在批次之间、重启和流末截断。修改未来波形不得影响此前提议。等待期 Qwen 与测量工具调用数应为零，等待期原始波形仍按策略进入缓冲。跳过的区间不得自动标成阴性或阳性。

**第二层，固定游标审查。** 先核对 1560、1650、1660、1720、1800 秒的代表故障。1660 秒另做“同样当窗证据、普通空闲／刚刚关闭”配对；确认原始理由、观察和动作相容。固定输入能检查它是否提出了合理的待办，不能检验等待后的收益。

**第三层，连续回放。** 先保持历史格式、编号、Founder、工具、预算和解码设置相同，按下列顺序比较。各组可用相同记忆检索能力；报告实际读取与使用次数。

| 组别 | 起止权限 | 什么时候唤醒 | 主要检验 |
|---|---|---|---|
| 基线 | 当前回退版 Qwen 接口＋原追踪器 | 每十秒 | 复现已知问题 |
| 对照一 | 改善观察接口，保留原确认规则 | 每十秒 | 当前知识表达与接口修改的收益 |
| 对照二 | Qwen 自主 OPEN/CLOSE，允许 UNCERTAIN、DEFER 和跨窗待办 | 每十秒；待办总在下一批复核 | 自主起止；同时提供可追溯的等待基线 |
| 主实验 | 与对照二相同 | 由 Qwen 选择下次复核时刻 | 同一套动作、待办及记忆下，自主决定**何时复核**有无额外收益 |

先用 04936 检查行为，再冻结配置扩展到未参与调试的记录。若主实验减少了调用，应增加**同等调用预算的固定间隔或预定时间表**，检验收益来自有选择地等待还是仅因更少巡视。若要声称记忆检索的独立贡献，在相同调度下配对比较是否提供相应历史。若要区分提示与上下文，保留“原接口／新接口 × 原上下文／精简上下文”的固定证据消融；调度主实验先不跨这两个变量。

## 10. 怎样评价这一版是否值得保留

- **事件效果。** 沿用原一对一事件匹配及 IoU ≥ 0.5。报告事件 F1、误开、漏开、错误关闭、漏关和短事件召回。对整条预定评价时间轴评分，完整落在等待期内的参考事件仍计入分母。
- **不确定性与覆盖。** 分开统计 UNCERTAIN、主动 DEFER、实际未评估以及 ACTION_ERROR。输出明确判断覆盖率和未知时间；不得把未观察时间当作正确阴性。同等覆盖率下比较错误率，同时报告全量指标。
- **等待有没有换来新信息。** 对每个待办追踪“最初证据 → 请求等待多久 → 实际等了多久 → 读取或新增了什么 → 是否解决 → 结果是否与参考一致”。报告等待次数、解决率、重复延迟率、流末未决率、等待后纠正与新增的错误；按待办去重，不能将重复唤醒算作多次成功。问题是否解决、判断是否正确分别评分。
- **时间与成本。** 分开报告估计边界误差、实际首次报警与关闭延迟、观察到延迟的病例数，以及没有报警或没有关闭的病例数。分别记录信号时间上等待的秒数和计算墙钟耗时，并报告每记录小时的唤醒、Qwen 调用、记忆检索、测量和 token 消耗。
- **结论门槛。** 先比较自主和固定唤醒组在同等资源或覆盖水平下的误开、误关、延迟及漏掉的短事件。只有在独立记录上体现可复现的权衡改善，才把收益归因于主动延迟。单独看到更少的 CLOSE、更少的调用或更少的明确错误，都不足以作此结论。
