# 从 ReAct 取证到事件决策：ECG Agent 一次复核怎样运行

适用于房颤与房扑合并事件的流式研究。旧 C/D 使用基线 `9bd292a`。自主模式已接入本地正常回放入口，第 7 节给出当前实现、调用配置和评分口径。[已有研究方案](ECG_AGENT_WINDOW_EVENT_DECISION_PLAN.md) · [自主事件提示词](prompts/autonomous_event_v1/README.md)

## 1. 先分清谁知道什么

**“开启事件”是一次动作，“事件开放中”是动作执行后的状态。** 本任务只追踪 AF/AFL。Qwen 提交 OPEN 并通过校验，表示登记一次 AF/AFL 发作的开始。从登记成功到 CLOSE 成功之前，账本一直显示“正在追踪这次发作”。例如 Qwen 在第 20 秒登记发作，估计它开始于第 16 秒。第 20 秒是登记时刻，第 16 秒是估计起点。到第 30 秒，这条记录仍可处于开放状态，即使当前心律一时看不清。

假设记录播放到第 40 秒。程序知道哪些波形已经到达，知道第 20 秒曾成功登记一个事件。它并不知道这个事件在生理上是否仍然持续。Qwen 接下来要用测量回答第二个问题。二者各有一个状态，各有自己的来源。

| 对象 | 内容 | 谁产生 | 怎样使用 |
|---|---|---|---|
| 事件状态 | 当前没有开放事件，或当前有一个开放事件 | 账本根据已成功执行的 OPEN、CLOSE 维护 | 决定本轮可操作的对象。事件仍开放时，未观察的间隔仍可记为未知 |
| 观察状态 `assessment` | 当前评估区间的证据支持目标、反对目标，或无法判定 | Qwen 使用本轮可见的工具结果和记忆作出判断 | 约束可以提出什么动作，也让研究者能单独评价模型读证据的能力 |
| 待复核问题 | 例如“分数下降是短暂波动，还是节律已经改变？” | Qwen 主动延迟时提出，程序保存并在唤醒时归还 | 保留一个尚待解决的问题。待办可以在尚无正式事件时存在 |

房颤和房扑均属于目标。一项可用测量支持房扑时，房颤分数低并不会抵消该支持。账本显示“无开放事件”只说明此前尚未登记或上一事件已关闭，不能作为本窗无房颤的测量证据。

## 2. 从收到信号到下次醒来的四步

### 第一步：读账本，明确这次是在看哪一段

运行时提供当前游标、本次评估区间、还能重新测量的原始波形范围、可用导联、剩余预算、近期实测摘要、最近一次已执行事件变更和上次待办。首窗的事件与历史为空。一次关闭被拒绝后，快照应显示事件仍开放；成功关闭后，则显示当前无开放事件。不能让模型从上轮理由猜执行结果。

### 第二步：Qwen 用 ReAct 取证

Qwen 根据眼前疑问选择一个工具，读返回值，再决定是否继续。想了解亚型分数，可对一个导联的完整十秒调用 `score_ecgfounder`。怀疑信号干扰，可查质量或另一导联。关心节律是否变化，可比较已经到达的前后区间。需要以前的实测详情或事件事实时，可调用 `retrieve_memory`。程序记录每项返回的时间、导联、成功状态和引用 ID。

这里有两个不同的停止点。调用 `finish_measurements` 只结束**本轮取证**，随后仍要提交观察和动作。选择 `DEFER_DECISION` 则意味着本轮已经评估了现有证据，并决定**以后再处理某个具体问题**。如果备用导联现在可测且很可能解决问题，Qwen 可以立即补测，无须先预约。工具继续调用也有成本，模型可以在无有价值补测时以不确定结束取证。

### 第三步：形成观察状态，注明它适用于哪段时间

| Qwen 的观察 | 需要说得通的问题 |
|---|---|
| `SUPPORTS_TARGET` | 当前哪项成功的节律测量支持 AF 或 AFL？仅仅“尚未证实结束”不能提供正向支持 |
| `AGAINST_TARGET` | 当前哪些可用测量使“这段仍是 AF 或 AFL”较难成立？反对持续并不自动给出终点 |
| `UNCERTAIN` | 是未测、不可用、可用结果相互冲突，还是信息本身区分力不足？若称冲突，指出可比较时段内相反的观测 |

本轮调用过程中可以暂时拿不准，并继续补测。最终保存的是截至提交时的观察、所用证据和简短依据。当前窗的判断与事件估计边界可以落在不同区间，引用需要各自对得上。若当前窗完全未测，不能把之前的高分延用成新的阳性标签。

### 第四步：Qwen 根据观察和账本决定动作，程序校验后执行

| 账本与证据条件 | Qwen 可以怎样做 | 成功后的结果 |
|---|---|---|
| 无开放事件，本窗有正向依据，认为足以登记 | `OPEN` | 立即登记正式事件，独立保存估计起点与实际报警时刻。首窗就看到目标但起点不可见时，记录最早支持区间和“起点未观察到” |
| 还没登记发作，本窗没有提示需要追查的异常 | `RECORD_ONLY` | 保存本窗观察，账本仍为空闲 |
| 已经在追踪一次发作，本窗继续支持 AFL，没有新的疑问 | `RECORD_ONLY` | 把本窗证据追加到同一次发作，不重复登记开始 |
| 还没登记发作，本窗疑似新发 AFL，目前证据不足 | `DEFER_DECISION` | 保存疑问“是否已经开始？”和下次复核时刻，暂缓登记开始 |
| 已经在追踪一次发作，本窗分数下降，结束与否或结束边界尚不清楚 | `DEFER_DECISION` | 保存疑问“是否已经结束、结束在何处？”和下次复核时刻，账本中仍保留这次发作 |
| 已有开放事件，有反对持续的节律依据，又能定位或夹定实际转变 | `CLOSE` | 关闭当前事件，存下边界点或边界范围、证据引用和实际关闭决定时刻 |

每个动作在流仍继续时都可以安排下次巡视。只有 DEFER_DECISION 要交代“还要解决哪个问题、希望得到什么新信息”。自主模式下，未到预约时刻只缓冲信号；请求落在两个批次之间时，分别记录期望时刻和实际唤醒时刻。流末仍开放的事件记右截断，未解决待办保留。跳过的时段进入覆盖和漏检统计。

**一次最终提交足够。** 第三、四步是可分别审查的两个判断，可在同一次 `submit_event_decision` 中返回。账本状态由程序给出，观察和动作由 Qwen 给出。程序能检查空账本禁止关闭、引用是否已到达、OPEN 是否有正向观察、CLOSE 是否有反向和边界依据等条件。程序仅凭一个合法时间戳无法证明生理边界正确。单次联合输出也只证明两个字段可以分别检查，不能据此断言模型内部一定按某个先后顺序推理。

## 3. 把四步串成一个事件

下例为合成教学轨迹，秒数及测量表现不来自实验结果。模型只在当时游标处看到已到达信息。

| 实际游标 | 进入本轮时 | Qwen 取得的证据与观察 | Qwen 选择及账本结果 |
|---|---|---|---|
| 10 秒 | 空账本、无历史 | 测 0–10 秒。假设可用测量反对目标，填 AGAINST_TARGET | RECORD_ONLY，保持空闲，20 秒再看 |
| 20 秒 | 空闲 | 10–20 秒主导联支持 AFL，备用导联也提供支持，填 SUPPORTS_TARGET | OPEN，20 秒实际报警。若只能定位到区间，就保留区间精度；没有理由把游标填作精确起点 |
| 30 秒 | 已开放 | 20–30 秒仍支持 AFL，填 SUPPORTS_TARGET | RECORD_ONLY，把这段支持加入已有事件，40 秒再看 |
| 40 秒 | 已开放 | 主导联分数下降。Qwen 补查另一导联、核对质量，仍得到相反的可用测量，填 UNCERTAIN 并注明冲突 | DEFER_DECISION，留下“短暂波动还是结束”的待办，请求 60 秒复核 |
| 50 秒 | 已开放，有待办 | 只有新数据到达，没有唤醒 Qwen | 保留波形，不生成该窗的模型判断 |
| 60 秒 | 已开放，因待办唤醒 | Qwen 回读最后支持测量，并检查仍保留的间隔。如果发现有依据的转变，且当前证据反对持续，填 AGAINST_TARGET | 若转变只能夹定在 36–39 秒，CLOSE，记录估计范围及 60 秒实际提交。若新测量反而支持持续，则 RECORD_ONLY，撤回结束疑问；若仍不清楚，可再次 DEFER |

**40 秒并非一定要等。** 同一处主导联低分，如果补测发现主导联有干扰、备用导联仍可靠地支持 AFL，就可以在 40 秒给出 SUPPORTS_TARGET 并 RECORD_ONLY。如果当时已有反向和充分边界证据，也可以在 40 秒直接 CLOSE。反过来，单独一个 AGAINST_TARGET 仍允许挂起终点问题。这些分支体现观察对动作的约束，也保留模型自主选择的空间。

## 4. 与运行代码和原研究方案逐项对照

| 环节 | 实际运行的回退版 C/D | 已有自主事件研究方案 | 本文进一步明确的内容 |
|---|---|---|---|
| 输入与 ReAct | 十秒窗推进；进入 review 时可无当前测量。Qwen 能自主测量、读写记忆、结束测量，再进入独立最终阶段 | 沿用这些工具和因果约束，增加按预约唤醒 | 保留 ReAct。把“取证完成”和“延迟事件判断”作为两个不同操作记录 |
| 状态 | tracker 提供 IDLE、CANDIDATE、ACTIVE 等；模型还要提交窗口 interpretation | 提出独立的 assessment、event_action 和 next_review_s | 区分**进入复核前已经发生的事件事实**和**复核后产生的观察**，写明谁提供、何时生效 |
| 解释与动作 | `KEEP_OPEN` 和 `support` 强制互相对应；`CLOSE` 要求 `negative`。成功时直接采用模型提交的 interpretation | 已提出三种观察、四种事件动作 | 明确哪些组合有依据，特别是“支持＋仅记录”“反对＋延迟”“不确定＋当场继续补测”各发生在哪个阶段 |
| 开始 | IDLE 下 support 建候选，连续支持达到规则确认条件才正式转为 ACTIVE，默认两窗 | 原规则作为对照，自主组允许首窗正式 OPEN | 观察只是事件提议的依据；自主组只有成功执行 OPEN 才建立正式事件 |
| 结束 | 已确认事件可由 Qwen 请求 CLOSE。C/D 的纯模型关闭配置没有启用规则兜底。旧接口让模型填 event_id 和单个 end_s | 当前事件身份由程序绑定，允许点、范围和截断 | 将“反对持续”“能够定位终点”“关闭请求真的执行”分别记入评价 |
| 时间和待办 | 逐窗进入复核。旧 DEFER 后的 negative/conflict/unavailable 仍送给 tracker；没有模型选定的唤醒时间 | 已提出预约、待办和唤醒 | 明确等待中谁还能工作、哪些时间没有模型判定，以及醒来后怎样解决、撤回或延续同一疑问 |
| 证据与错误 | 已有工具账本、动作日志和窗口历史，提交错误另有 ACTION_ERROR，失败路径返回 unavailable | 保留证据、正式事件和待办三类记录 | 把模型原始提议、校验结果、已执行状态串起来。失败不得冒充节律反证、主动等待或成功关闭 |

**与原方案的关系。** 三种观察、四个动作和自主预约已在原方案提出。本文新增的是明确的工作时序、每步输入输出、关键分支及可检查的实施条件。无需为“先观察、再行动”新增第二个 LLM、额外推理回合或新的生理分类器。

## 6. 如何验证“观察真的被用于决策”

1. **先查协议。** 空账本拒绝 CLOSE。无正向依据拒绝 OPEN。已有事件但没有局部转变依据时，不能仅凭末次心搏提交精确终点。取证阶段暂时看不清时，可以当场补测。最终观察为 AGAINST_TARGET 时，可以保留事件并挂起边界疑问。检查失败均单列。
2. **固定证据，改变账本。** 同一份正向测量，在无事件和有事件两种快照下分别提问。合理表现是观察方向可保持一致，而可执行动作随账本变化。不要给新模式因 schema 禁止非法关闭记为临床识别收益。
3. **固定账本，改变证据。** 在有开放事件时分别呈现可靠持续支持、单一低分、真实导联分歧、可定位或仅可夹定的转变。检查方向、所引证据、边界形式和动作是否相容。不能硬性要求每次改一个分数就改变动作。
4. **连续运行。** 先与旧 C/D 及两窗规则对照，再在相同新接口下比较固定复核与自主预约。保留真实动作轨迹。分别报告错误观察、观察合理但动作不当、合法提议被拒、错误执行、等待后仍未解决。另报事件 F1、窗口覆盖、短事件漏检、实际报警与关闭延迟、模型及工具耗时。

如果研究要进一步证明“显式 assessment 是否增加了模型判断能力”，可在相同证据下另设只提交事件动作的对照。联合输出能提高可追溯性；能否提高事件性能需要上述实验验证。

## 7. 本地代码、回放入口与评分口径

| 运行条件 | 入口与配置 |
|---|---|
| 原 C/D 基线 | 保存在原实验工作树，继续使用当时的提示与参数 |
| Qwen 决定起止，每十秒复核 | 主项目的 `event-react` 策略，加载 [固定复核配置](../configs/ecg/react_qwen_episode_fixed.json) |
| Qwen 决定起止并预约复核 | 相同入口，加载 [自主预约配置](../configs/ecg/react_qwen_episode_autonomous.json) |

在已配置 AFDB、模型和 Qwen 环境的机器上，从项目根目录运行以下入口。两个条件分别使用各自的配置和输出目录。一次运行选择一个主导联，也可通过既有参数指定两路。实际 GPU、模型和数据路径使用实验机器的配置。

```bash
python -m cardioagent.ecg_agent.experiments.runner --mode live --policies event-react --workers 1 --threads 2 --device cuda:0 --channels ECG1 --llm-config configs/ecg/react_qwen_episode_fixed.json --output runs/episode-fixed
python -m cardioagent.ecg_agent.experiments.runner --mode live --policies event-react --workers 1 --threads 2 --device cuda:0 --channels ECG1 --llm-config configs/ecg/react_qwen_episode_autonomous.json --output runs/episode-autonomous
```

- 两个配置都使用最多 11 轮取证交互，加一次独立最终提交。提交被拒后可重试一次。窗口内工具预算另外设为 12。预约上限为当前游标加 120 秒，对应当前信号缓冲时长。超出限制会返回字段错误。两次提交都失败时，记录 ACTION_ERROR 并在下一批重试复核。
- [运行提示](../src/cardioagent/ecg_agent/prompts/autonomous_event_v1.json)按账本状态、取证或提交阶段、是否有待办及复核模式拼装。实际运行发送英文。恢复待办后要说明解决、撤回或继续等待。模型实际收到的消息和工具定义保存在每条记录的 `qwen_calls.jsonl.gz`。
- 正式事件区间保存在 `intervals`。范围边界取中点用于事件 F1；首次观察时发作已经存在，则使用最早有支持的区间起点。到流末仍在追踪时，区间截断于流末，账本保留 `right_censored`，实际关闭决定时刻为空。
- 自 v1.3 起，Qwen 在一次最终提交中为每个引用填一个角色。支持房颤或房扑用 `SUPPORTS_TARGET`，反对两者用 `AGAINST_TARGET`，质量、失败或仅帮助描述边界的测量用 `CONTEXT_ONLY`。角色由模型解释；原始测量可用证据 ID 回查。同一时段有相反归因，整窗须填 `UNCERTAIN/conflicting`，重叠秒数列入 `conflict_intervals` 和 `unknown_intervals`。正反证据分别位于转变前后时可用来夹定边界。
- 主指标 `burden_score` 用正式 `intervals` 的并集秒数除以完整评价时长。补充指标 `supported_burden_score` 用 `burden_intervals` 的并集，只累计有正向归因且无冲突的覆盖，包括 RECORD_ONLY 时的支持。质量测量、未观察时段及边界范围内的不确定时间均不增加证据支持时长。旧预测缺少这份账本时，补充指标记为 null；显式空列表对应零支持时长。两项误差均按百分点报告。
- AF 负荷评分采用任务给出的 floor，缺省 0.02。例：100 秒内报告 [10,40)，其中仅 [10,20) 有证据支持，参考负荷为 25%，则主负荷为 30%、得分 0.80，证据负荷为 10%、得分 0.40。Event F1 按提交顺序，用原始事件区间逐个和参考区间匹配，默认 IoU ≥ 0.5。一次事件追踪输出可派生两项分数；论文基准将定位与负荷设为独立任务。[官方评分器](https://github.com/CuCl-2/ECG-Scroll/blob/main/ecgscroll/verify.py) · [官方负荷任务说明](https://github.com/CuCl-2/ECG-Scroll/blob/main/ecgscroll/run_llm_skim.py)
- `window_trace.jsonl` 逐批显示有没有唤醒、实际决定、预约时刻和工具次数。`event_updates.jsonl` 记录已执行变更及待办进展。`assessments.jsonl` 保存通过校验的观察。`llm_steps.jsonl` 包含失败与重试，原始测量在 `evidence.jsonl`。
- 正常实验入口在每个到达批次后保存可校验的进度。中断后用相同配置、输入和输出目录重启，可以恢复已经提交的观察、事件、历史、待办和预约。中断批次可能重算；完整记录仍走原有记录级校验。
- [端到端测试](../tests/runtime/test_autonomous_events.py)使用脚本化模型通过正常实验入口驱动实际工具协议。它验证程序执行和评分逻辑，真实模型的误开、误关、漏检与延迟需要独立回放测量。
