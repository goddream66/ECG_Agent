# AFDB Agent 0.6/0.4 状态阈值实验

配置：`configs/ecg/policy_hysteresis060040.json`。`threshold=0.6` 为未确认事件的启动阈值，`continue_threshold=0.4` 为已确认事件的持续阈值。未配置持续阈值时保留旧版本的单阈值行为和配置序列化。

候选及未确认的 UNKNOWN_HOLD 使用0.6；已确认的 ACTIVE、PENDING_END、UNKNOWN_HOLD 使用0.4；关闭后重新使用0.6。每窗决策开始时确定阈值，主/次通道及临界复核使用同一阈值。逐窗日志和解释日志记录 decision_threshold。原始模型分数不变；质量、复核预算、两窗确认/结束、十秒未知宽限、周期复核等参数保持不变。

旧 fixed 证据及 legacy-dual 不自动获得新阈值语义。运行新配置时必须显式选择 `--policies event-adaptive`；runner的默认策略矩阵保持不变。未知策略名或不兼容组合会失败，避免重复运行不需要的基线。

范围：既有 ECG-Scroll AFDB 全量23条完整记录，分别以ECG1/ECG2为主通道。四张GPU各一个进程、各两个CPU计算线程。每个主通道按记录时长分为两个互斥分片，合计46个记录级Agent任务；不切分单条记录内部状态。核验分片覆盖完整且无重复。

使用既有AFDB预处理、已到达窗口和真实按需ECGFounder调用。无未来分数表输入Agent。新结果写服务器data盘独立目录。比较冻结的简单0.6/0.4滞回、上一轮0.8 Agent；基线复用需核验任务、模型、预处理、评价参考及文件指纹，不重复宣称缓存的真实GPU成本。

评价沿用一对一贪心IoU>=0.5、独立节律有效范围、时间/事件/短事件/碎片/负荷/未知覆盖及调用指标；记录配对Bootstrap 2000次、种子20261114。AFDB已用于开发，属于探索性对照，不宣称独立外部泛化。
