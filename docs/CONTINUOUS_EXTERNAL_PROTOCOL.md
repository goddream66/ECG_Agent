# LTAFDB 连续复核实验

## 问题

在连续二十分钟的双导联记录中，按需调用 ECGFounder、保存已接受的事件支持依据并由 Qwen 复核边界，能否改善事件检测、误报时长或测量成本？

## 入组与重放

- 排除首轮 LTAFDB 探针的 12 个记录 ID。使用源数据清单核对排除表出处。
- 在至少有连续 1,200 秒有效标注范围的记录中，按固定散列顺序抽取 4 条。每条在符合时间范围的十秒格点上按另一散列选择一个起点。同一记录只出现一次。确定片段后才读取其 AF/AFL 区间用于评分。抽到全阴性、全阳性或正在发生的事件均保留。
- 每段从空事件账本开始，保留全部 120 窗。模型只能看到游标之前的测量。离线评分裁切首尾跨界的参考事件，另统计完全可观察的起点和终点。
- 在读取新片段的结果前，将主策略冻结为提交 `ae62600` 的 `accepted_support_memory=true`，沿用此前外部试验的其他参数。本组使用原测量分箱与原提示呈现。双导联不确定分数的解释和上下文压缩各有单独配对实验。

## 对照

1. 主基线按每窗每导联的 `max(AF,AFL)` 与 0.5 比较，两导联一致才给出方向，两窗支持开事件、两窗反对关事件。
2. 加入一窗开启、两窗结束的基线，检验短事件敏感性。
3. 比较按需读取第二导联的规则，以及在 Agent 实际取得的对齐 Founder 结果上重放的两窗规则。后者共用了 Agent 的选窗与选导联结果，归因仅限后续决策。

## 报告与判读

逐记录和总体报告事件 TP、FP、FN、IoU ≥ 0.5 的 Micro F1，并报告 4 个片段 F1 的均值、非目标报警秒数、漏掉的目标秒数、负荷误差、首次在线达到匹配标准的时刻，以及 Founder 调用、Qwen 调用、token 和实际用时。标明边界误差各自的可观察匹配数。分别记录实时决定时刻和回溯估计的边界。

如果节省 Founder 调用但增加总耗时，两项分开报告。相同事件 F1 下的时间覆盖改善应列出贡献记录。4 条记录支持探索性的配对比较，后续扩大连续记录覆盖范围再评价稳定性。
